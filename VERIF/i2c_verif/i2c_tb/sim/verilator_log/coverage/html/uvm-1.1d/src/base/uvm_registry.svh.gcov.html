     304             : // Group: Usage
     305             : //
     306             : // This section describes usage for the uvm_*_registry classes.
     307             : //
     308             : // The wrapper classes are used to register lightweight proxies of objects and
     309             : // components.
     310             : //
     311             : // To register a particular component type, you need only typedef a
     312             : // specialization of its proxy class, which is typically done inside the class.
     313             : //
     314             : // For example, to register an UVM component of type ~mycomp~
     315             : //
     316             : //|  class mycomp extends uvm_component;
     317             : //|    typedef uvm_component_registry #(mycomp,"mycomp") type_id;
     318             : //|  endclass
     319             : //
     320             : // However, because of differences between simulators, it is necessary to use a
     321             : // macro to ensure vendor interoperability with factory registration. To
     322             : // register an UVM component of type ~mycomp~ in a vendor-independent way, you
     323             : // would write instead:
     324             : //
     325             : //|  class mycomp extends uvm_component;
     326             : //|    `uvm_component_utils(mycomp);
     327             : //|    ...
     328             : //|  endclass
     329             : //
     330             : // The <`uvm_component_utils> macro is for non-parameterized classes. In this
     331             : // example, the typedef underlying the macro specifies the ~Tname~
     332             : // parameter as "mycomp", and ~mycomp~'s get_type_name() is defined to return 
     333             : // the same. With ~Tname~ defined, you can use the factory's name-based methods to
     334             : // set overrides and create objects and components of non-parameterized types.
     335             : //
     336             : // For parameterized types, the type name changes with each specialization, so
     337             : // you can not specify a ~Tname~ inside a parameterized class and get the behavior
     338             : // you want; the same type name string would be registered for all
     339             : // specializations of the class! (The factory would produce warnings for each
     340             : // specialization beyond the first.) To avoid the warnings and simulator
     341             : // interoperability issues with parameterized classes, you must register
     342             : // parameterized classes with a different macro.
     343             : //
     344             : // For example, to register an UVM component of type driver #(T), you
     345             : // would write:
     346             : //
     347             : //|  class driver #(type T=int) extends uvm_component;
     348             : //|    `uvm_component_param_utils(driver #(T));
     349             : //|    ...
     350             : //|  endclass
     351             : //
     352             : // The <`uvm_component_param_utils> and <`uvm_object_param_utils> macros are used
     353             : // to register parameterized classes with the factory. Unlike the the non-param
     354             : // versions, these macros do not specify the ~Tname~ parameter in the underlying
     355             : // uvm_component_registry typedef, and they do not define the get_type_name
     356             : // method for the user class. Consequently, you will not be able to use the
     357             : // factory's name-based methods for parameterized classes.
     358             : //
     359             : // The primary purpose for adding the factory's type-based methods was to
     360             : // accommodate registration of parameterized types and eliminate the many sources
     361             : // of errors associated with string-based factory usage. Thus, use of name-based
     362             : // lookup in <uvm_factory> is no longer recommended.
